# PlugBot 승선 시점 MVP 상태 (2026-11-08, 팀 Land2Sea)

전담멘토께 드리는 문서입니다. 본선 평가가 "본선 기간 중 수행한 개발"을 중심으로 한다는 안내(11/7)에 따라, 승선 시점에 무엇이 되어 있고 무엇이 안 되어 있는지를 먼저 밝힙니다.
같은 내용이 저장소(github.com/gawbi/plugbot) 태그 `boarding-20261108`과 `docs/team/baseline_20261108.json`(데이터셋 수, 체크포인트, 결과 파일 목록을 자동으로 적은 것)에 있습니다.
본선 중 늘어난 것은 `python3 tools/onboard_report.py`가 이 기준선과 비교해 자동으로 셉니다. 언제든 보여 드리겠습니다.

## 작품 한 줄
전기차 충전 로봇이 하던 "플러그 꽂기"를, 흔들리는 전기 선박의 충전 소켓으로 옮기는 작은 로봇팔. 파도를 예측해 잔잔할 때 꽂고(시뮬레이션), 사람의 원격조종 시범을 모방학습(ACT)해 실물이 혼자 꽂는다.

팀: 김광빈(팀장, 로봇과 학습), 나다원(발표), 이주은(사업화와 데이터), 조선기(하드웨어).

## 본선 기간(11/8~11/10)에 하려는 것
1. **실물 성공률 측정**: 체크포인트 3개(8만, 12만, 16만)를 정지 10회와 흔들림 10회씩 비교해 하나를 고르고, 그것으로 정지 20회 + 흔들림 20회. 판정은 사람이 보고 버튼으로, 실패도 센다. 95% 신뢰구간(Wilson)과 함께 보고.
2. **선상에서 시범 30개 추가 수집 → 밤에 추가 학습 → 다음 날 같은 방법으로 재측정**: "데이터를 더 모으면 더 잘 꽂는가"를 실물로 확인. 나빠지면 나빠졌다고 보고.
3. 선상 실행 기록으로 실물 ↔ UR10e 나란히 영상, 로봇 혼자 꽂는 장면 촬영 → 발표 7, 9, 12장 갱신.
4. 부스 화면의 흔들림 실측 그래프와 실시간 이종 원격조종을 처음 실제로 돌려 봄(됐는지 안 됐는지 그대로 기록).
5. 하드웨어: 카메라 고정 보강, 흔들기 모터 전원 분리, 현장에서 생기는 문제를 사진과 함께 `docs/troubleshooting.md`에 기록.

## 측정 규칙
- 1회 = 25초 실행(다시 계획 3.3초), 끝나면 사람이 [꽂힘]/[못 꽂음] 버튼. 애매하면 못 꽂음. 판정 없는 실행은 세지 않는다.
- 모든 실행은 `data/rollouts/<시각>/`에 두 카메라 영상과 관절 기록이 남는다(멘토가 확인 가능).
- 추가 학습 전후는 같은 부스, 같은 소켓 자리 배분(가운데, 왼쪽, 오른쪽)으로 잰다.

## 데이터 출처와 이용 조건
`docs/data_sources.md`: 직접 수집한 데이터(시범 134개, 실행 기록), 공공데이터 4종(부산항만공사 선박 집계, 기상청 해양기상부이, 전력거래소 SMP, 국립해양조사원 파랑)의 제공기관과 이용 조건, 제3자 소프트웨어(LeRobot, MuJoCo, Isaac Sim 등)의 라이선스, 참고 영상(현대차 ACR 공식 영상, 인용만).
아직 못 읽은 이용 조건(해양조사원 파랑 자료 등)은 "확인 필요"로 적었고 11/8까지 확인합니다.
