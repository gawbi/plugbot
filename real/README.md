# 실물 시연 진행 순서 (SO-101, 맥에서 실행, GPU 불필요)

웹캠 영상 → 마커로 소켓 자세 → 카메라→로봇 보정 → AR 예측, 정온 구간 → IK → SO-101.
MuJoCo 실험과 같은 전략과 상태 기계를 쓴다(`plugbot/control.py`).

본선 배치는 **side**다: 흔들림 갑판판에 세운 판(`side_mount`)을 볼트로 붙이고 소켓을 판 앞면에 단다.
L자 플러그(`plug_L`)로 옆에서 꽂는다. 자동차 충전구(`car_port_side`)는 로봇 왼쪽 50°에 둔다.
예선 배치(top, 갑판 위 소켓에 위에서 꽂기)는 `PLUGBOT_LAYOUT=top`을 붙여 실행하면 그대로 쓸 수 있다.

## 0. 실물 없이 검증한 결과 (`python -m real.dry_run`, 2026-10-31, side)

MuJoCo로 앞 카메라 영상(1280 × 720)을 렌더링해 아래 코드를 그대로 돌렸다(조건당 10회, 정답 위치로 채점).
파도는 부두에 옆으로 댄 배(좌우 롤).

| 조건 | 추종 | 예측(정온 구간) |
|---|---|---|
| 정지 소켓 | 100% | 100% |
| 모형 파고 4 cm | 70% | 100% |
| 모형 파고 6 cm | 30% | 100% |

- 보정(소켓 8곳 중 6곳 사용, 핀 끝 1 mm 잡음): 점별 오차 RMS 0.8 mm, 카메라 회전 1.8°. 보정 점들이 소켓 둘레에 모여 있어
  카메라 자체 위치는 12 mm 틀리지만, 작업 영역 안 오차는 1 mm 안팎이다.
- 소켓 추적: 판 마커 4개 + 탭 마커로 입구 위치 오차 0.4~0.7 mm(앞 카메라 자리에서, 팔이 일부 가려도).
  로봇 받침 바로 옆에 카메라를 두면 팔이 판 마커를 가려 삽입 중 오차가 3.8 mm까지 커졌다.
- 실물 흔들림 갑판 움직임(힌지 축 둘레 회전, `HingeDeckMotion`)으로도 시뮬레이션했다(20회):
  정현파 진폭 4, 8 mm는 예측, 추종 모두 100%, 불규칙파 Hs 2 cm는 예측 90%, 3 cm는 85%.

## 1. 살 것

준비물 체크리스트(김광빈, 조선기 따로)가 저장소 밖에 있다. 요약: M5 × 40 볼트 2, M4 × 16 볼트와 너트 12쌍,
유전원 USB 허브, 자석, 서보와 아두이노(흔들림), (RealSense가 안 되면) C270.

## 2. 출력과 조립

- `cad/PRINT_GUIDE.md` 그대로. 소켓 2, L자 플러그 2(1개 여분), 세운 판 1, 자동차 충전구 1, 갑판 2, 손목 카메라 거치대 1.
- 인쇄(실제 크기 100%, 눈금자로 확인): `real/print/`
  - `01_소켓마커.pdf`: 선박 소켓 탭에 id 0, 자동차 충전구 소켓 탭에 id 10. 마커 오른쪽이 탭 바깥쪽(위)을 향하게.
  - `05_판마커_선박.pdf`(id 5~8): 갑판 위 세운 판 앞면에 붙이고 볼트 구멍을 뚫어 소켓을 그 위에 고정. 로봇 쪽에서 본 모습 그대로다.
  - `06_판마커_자동차.pdf`(id 15~18): 자동차 충전구 판 앞면에. 두 소켓이 한 화면에 보여도 번호로 구분한다.
  - `03_카메라보정판.pdf`: 평평한 판에 붙인다.
- 놓는 자리(로봇 베이스 중심 기준, 책상 위, 로봇은 높이 100 mm 받침 위):
  - 흔들림 갑판: 베이스 중심을 정면 331 mm, 힌지가 로봇 쪽. 세운 판 앞면이 정면 346 mm, 소켓 입구가 300 mm에 온다.
  - 자동차 충전구: 같은 자리를 어깨 회전축(베이스 중심에서 정면 39 mm) 둘레로 왼쪽 50° 돌린 곳, 판 앞면이 로봇을 본다.
  - 앞 카메라: 정면 60 mm, 오른쪽 220 mm, 책상 위 400 mm. 두 소켓 사이(정면 260 mm, 왼쪽 100 mm)를 바라본다.
  - 손목 카메라: 키트 카메라를 공식 손목 거치대로 그리퍼에. 옆으로 꽂을 때는 그리퍼가 아래를 봐서 깔때기 입구는 거의
    안 보인다(삽입 제어는 앞 카메라만 쓴다. 손목 영상은 ACT 학습용).

## 4. 순서 (처음 한 번)

1. 웹캠 보정: `python -m real.vision calib --cam 0` → 보정판을 여러 각도로 15장. RMS 1 px 안팎이면 된다.
   RealSense D435는 컬러 영상이 일반 웹캠처럼 열린다(맥에서 번호를 `lerobot-find-cameras opencv`로 확인. 1280 × 720,
   화각 약 69°). 열리지 않으면 C270을 쓴다. 어느 카메라든 이 보정을 먼저 한다.
2. 추적 확인: `python -m real.vision show --cam 0` (자동차는 `--target car`) → 갑판을 움직이면 숫자가 따라 바뀌는지.
3. **관절 매핑 확인(필수)**: `python -m real.robots check --port /dev/tty.usbmodemXXXX`
   토크가 꺼진 팔을 손으로 움직여 화면 속 모델이 같은 자세인지 본다. 다른 관절은 `config/joint_map.json`의
   `sign`(-1)이나 `offset`(rad)을 고친다. 공식 URDF(so101_new_calib)와 LeRobot 보정 기준이 같아 대부분 그대로일 것이다.
4. 카메라→로봇 보정: `python -m real.calib --port ... --cam 0`
   토크를 끈 팔로 L자 플러그를 깔때기에 끝까지 꽂고(자석이 붙게) Enter. 갑판을 책상 위에서 앞뒤, 좌우로 3~5 cm씩 옮기고
   레버로 기울여 가며 6~8번. 보정 뒤에는 카메라를 건드리지 않는다.
5. 정지 소켓 10회: `python -m real.insert --port ... --cam 0 --trials 10 --strategy predictive`
6. 흔들림: 아두이노 시리얼에서 `s`(정현파). 같은 명령으로, `--strategy reactive`로도 돌려 비교한다.
7. 자동차: `python -m real.insert --port ... --cam 0 --trials 5 --target car`

## 안전

- 첫 시험은 `config/joint_map.json`의 `max_step_deg`를 3으로 낮춰 천천히.
- 마커를 0.5초 넘게 못 보면 그 자리에 멈추고, 3초가 넘으면 시행을 끝낸다. Ctrl+C로 언제든 중단.
- `--cam-delay`(기본 0.05 s)는 웹캠 지연. 흔들림에서 늘 늦게 꽂히면 0.08~0.12로 올려 본다.
- 서보 전원은 스위치 멀티탭에 꽂아 한 번에 끌 수 있게 한다.
